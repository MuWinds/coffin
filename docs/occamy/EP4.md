# EP4 实装与复测：4 卡上不成立（2026-11-11）

> 结论先给：专家并行（每卡装全部 40 层、只把专家切 4 份）已经跑通、数值正确，
> 但在这台机器上**两边都输**——预填充 3.7 倍慢、decode 0.65 倍。原因是结构性的，
> 不是调参能救的。代码保留（默认不启用），PP4 仍是生产拓扑。
>
> `SERVING.md` §8.5 里那行「EP4：M=1 下 0.95x（gloo）/1.37x（ixCCL）」是
> `qwen4exp` 的探针数字，`ixCCL` 那一路没有代码沉淀、复现不了。本文件是把它
> 接进 `qwen35` 之后的实测。

## 1. 实测（同一台机、同一份 W8A8 权重、贪心、同会话内先 PP4 再 EP4）

| 项 | PP4 基线 | EP4 | 比 |
| --- | --- | --- | --- |
| 2001 token prefill | **2305.6 ms** | **8506.8 ms** | **0.27x** |
| decode（5 token prompt） | 29.55 tok/s | 19.34 tok/s | 0.65x |
| decode（16 token prompt） | 27.46 tok/s | 18.89 tok/s | 0.69x |
| 输出质量 | 正确 | 短 prompt 正确、长 prompt 首个 token 就分叉 | — |

复现：`.tmp_stage/ep4/gate_ep.sh`（`MODE=pp` 是基线、`MODE=ep` 是待测侧），
经沙盒队列投，一侧约 1 分钟。

## 2. 两条结构性原因

**非专家算力被复制成 4 份。** EP 只切专家：注意力（10 层全注意力 + 30 层 GDN 递推）、
dense MLP、共享专家、norm 在每张卡上各算一遍。PP4 把这些按层切了 4 份，EP4 是 4 倍。
0.27x 与「4× 非专家 + 1× 专家」的算术同向，实测更差是因为激活侧还有
`tokens × top_k` 行的收拢与量化在每张卡上各做一遍（预填充 2001 token 时是 16008 行，
其中只有约 1/4 是本 rank 的有效行）。

**没有 P2P 的卡上，每层一次归约必然带一次全流同步。** 这张卡的跨卡写实测 2.4 GB/s，
归约只能经主机（共享内存 barrier 30-100 µs，gloo 291-420 µs）。而 decode 一步要
40 次这样的往返，每次都要等设备把队列排空才能读到值——主机预取被打断 40 次。
实测每层多付约 **445 µs**（(51.7 - 33.9) ms / 40 层），比裸归约成本大一个量级。
`qwen4exp` 在 decode 里插一次 `offsets[-1].item()` 同步就量到 +11.7%，量级一致。

**要让它成立，得同时满足**：有设备侧 P2P（归约不必过主机），或把 dense 也切掉
（那就退回 TP，而 TP 每层两次归约更死）。所以 4 卡上就地封存。

## 3. 实装踩到的一个安静错误：丢弃槽位带着真实投影值落回槽位 0

`moe_dispatch` 把不属于本 rank 的槽位丢掉、位置表尾部清 0，但分组内核仍然按 **`slots`**
行算完了它们（行序尾部指向 token 0），于是这些假行带着**真实投影值**、按「槽位 0 的
路由权重」加了回去。恒等映射时这批行不存在，所以单卡 / PP / TP 全都看不见这个坑。

症状极有辨识度：**第一个 token 正确，其后逐 token 变胡话**——预填充那一步没有这些行，
而 decode 每层都多算约 6 个假专家。修法：把逐行权重按 `arange(slots) < offsets[-1]`
清零，掩码留在设备上算；用 `offsets[-1].item()` 会引入每层一次 D2H 同步，那正是
上面第二条里那 445 µs 的来源之一。

## 4. 代码在哪

| 位置 | 内容 |
| --- | --- |
| `models/qwen35/ep.py` | 同机共享内存全归约：`all_reduce_sum`，`[1, 2560]` 一次 30-100 µs，替掉 gloo 的 291-420 µs；不依赖 `torch.distributed` |
| `models/qwen35/parallel.py` | `mode="ep"`、`expert_range()`（按专家号连续切）、`combine()`；加载器用 `get_slice` 只读本 rank 那段专家栈 |
| `models/qwen35/moe.py` | 局部专家表（全局号→本地号，-1 表示不在本 rank）、丢弃槽位清零、`_reduce` 的 ep 分支 |
| `tools/launch_occamy_ep.sh` | 四 rank 启动器（预建 /dev/shm 板、逐卡探卡、错峰启动） |

默认走 PP：`COFFIN_PARALLEL=ep` 才会启用，环境变量与共享区容量见启动器头部注释。
